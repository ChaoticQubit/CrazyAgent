# RCLI as an editable central leader harness

## Is reuse with selective customization a viable direction?

### Takeaway

Yes, conditionally. The selected hybrid is supported by the available source and license: reuse RCLI as the leader reasoning process, keep the Rust engine as the authority, and make a small maintained fork only if qualification exposes a missing integration surface. This assessment is static source qualification, not an executed integration, benchmark, or security audit.

### Cited Findings

- The official Backboard product page links to `Backboard-io/Backboard-R-CLI`. The current `main` commit observed on October 16, 2026 is `51bee17e02344de5fffd89523ce2b73d5042f216`, committed October 11, 2026. Pin this revision for qualification rather than depending on moving `main`. The manifest identifies version `3.0.4`. [Official product page](https://backboard.io/products/cli), [immutable commit](https://github.com/Backboard-io/Backboard-R-CLI/commit/51bee17e02344de5fffd89523ce2b73d5042f216), [manifest](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/package.json)
- The repository license is MIT, copyright 2026 Backboard. Its text permits modification, merging, distribution, sublicensing, and sale, subject to retaining the copyright and permission notices in copies or substantial portions, and includes warranty/liability exclusions. These are facts from the license text rather than advice about trademark, service terms, or dependencies. [License](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/LICENSE)
- This is a TypeScript/Bun implementation, not a Rust library. Its manifest depends on Ink, React, the TypeScript MCP SDK, Zod, and language-server packages. The CLI is the package entrypoint and the package is marked private. The existing source should therefore be treated as an application/process integration rather than an already published stable embedding SDK. [Manifest](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/package.json)
- The release builder declares Bun compilation targets for macOS arm64/x64, Linux arm64/x64 with glibc and musl variants, and Windows x64. The README describes distributed compiled binaries that do not require users to install Bun or Node. These declarations establish intended packaging support, not successful testing of CrazyAgent on each OS. [Release builder](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/scripts/build-release.ts), [README installation](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#install)

### Inferences

- A Rust main engine can host an RCLI sidecar without porting the reasoning loop to Rust. This preserves the user's Rust requirement while reusing an existing harness. The process boundary is an architectural recommendation based on the existing CLI packaging and entrypoint, not a verified ready-made CrazyAgent integration. [Manifest](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/package.json)
- Prefer an adapter against the pinned unmodified binary first. If a necessary host-control surface is absent, add only that surface in a thin fork and maintain an explicit upstream patch set. A complete rewrite would discard much of the source reuse benefit; no evidence from this qualification justifies one. [Entrypoint](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/entrypoints/cli.tsx)

### Gaps

- No dependencies were installed and no fetched source or installer was executed. Binary reproducibility, actual Windows/macOS/Linux behavior, distribution notices for bundled dependencies, upstream maintenance expectations, and release signing still need qualification.
- No published compatibility promise for the internal TypeScript classes or JSON event schema was established. Pinning and compatibility checks remain necessary even if the initial integration works without a fork.

## Can it run behind CrazyAgent's own TUI and desktop conversation?

### Takeaway

There is a credible starting point: headless one-shot execution with NDJSON output, resumable sessions, MCP tools, and an editable tool registry. That is materially better than scraping a TUI through a PTY, but it is not evidence of a complete bidirectional app-server protocol for interactive approvals, reconnect, and live multi-turn control.

### Cited Findings

- The CLI supports `--print` and `--format json`, including a prompt piped to standard input. Its entrypoint requires a print argument or piped input for JSON mode and routes both modes through headless execution. The entrypoint reads piped standard input to completion. This supports prompt-in/event-stream-out automation, not a demonstrated persistent interactive input protocol. [README JSON modes](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#one-shot-and-json-modes), [entrypoint](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/entrypoints/cli.tsx#L278)
- `JsonEventStream` emits records containing timestamp, session ID, sequence, source, type, and an `AgentEvent` payload. It is a usable candidate for a Rust adapter consuming structured events. The class does not itself establish durable host acknowledgements, event replay after disconnection, or reconnect ownership. [JSON event stream](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/core/session/JsonEventStream.ts)
- RCLI initializes configured MCP servers before building the agent controller. `ToolRegistry` supports registering, unregistering, retrieving, and filtering tools. This provides source extension points, but the manifest does not expose them as a public stable SDK. [Entrypoint MCP initialization](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/entrypoints/cli.tsx#L316), [tool registry](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/core/tools/ToolRegistry.ts)
- In headless execution there is no interactive permission prompter. Requests that would ask are denied unless allowed by an explicit project rule or bypass mode is deliberately selected. CrazyAgent must not solve this mismatch by silently enabling bypass. [README JSON modes](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#one-shot-and-json-modes), [entrypoint permission context](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/entrypoints/cli.tsx#L322)
- Native custom subagents have configurable tool/model/round limits and own contexts. Documented nesting stops at two levels. Launched background agents are capped at four concurrently, with additional runs queued; headless execution runs those agents inline. These are the harness's documented behaviors, not proof that it satisfies CrazyAgent's eventual large hierarchy ambition. [README custom subagents](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#custom-sub-agents)

### Inferences

- The smallest useful qualification is to expose narrow Rust-owned orchestration operations through an MCP server, run one RCLI leader turn, consume its NDJSON, approve the plan in CrazyAgent, and resume or invoke a later turn against the same logical conversation. Verify this using a temporary project with no real credentials in logs. Native RCLI subagents are distinct from separately launched Claude/Codex worker harnesses. [MCP initialization](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/entrypoints/cli.tsx#L316), [subagents](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#custom-sub-agents)
- If multi-turn process restarts and resume are insufficient, the smallest fork should add a stable bidirectional host protocol for user messages, tool-approval responses, cancellation, and event delivery. Keep that boundary separate from the TUI rendering code. Do not infer that NDJSON output already supplies these features. [Entrypoint](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/entrypoints/cli.tsx), [JSON event stream](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/core/session/JsonEventStream.ts)

### Gaps

- Bidirectional streaming input, safe approval round-tripping, cancellation of descendant processes, replay/reconnect after a client exit, exact tool hiding for a leader-only profile, and idempotent dispatch remain untested.
- No latency, memory-use, concurrency, restart cost, or high-worker-count measurement was performed. Proposed qualification duration is a planning judgment, not a benchmark result.

## Which backend, credentials, memory, routing, and authority does reuse actually provide?

### Takeaway

Backboard's hosted backend is optional for the CLI, but hosted memory is not included merely by downloading the CLI. Direct provider credentials and local compatible endpoints are supported. No inspected evidence establishes that RCLI can consume an existing Claude Code or Codex subscription login. Its provider router is not CrazyAgent's task/resource-aware worker router, and its permission prompts/checkpoints are not an independent verification boundary.

### Cited Findings

- The README explicitly supports direct Anthropic, OpenAI, Google, and OpenRouter keys without Backboard login, plus OpenAI Chat Completions, Responses, and Anthropic-compatible custom endpoints. Custom endpoints may use a stored key, an environment reference, or no authentication. Direct enabled keys take precedence for supported providers. Provider-specific OAuth and native cloud authentication require dedicated integrations. [Direct providers](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#use-your-own-model-providers), [custom providers](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#custom-model-providers)
- `BackboardClient` advertises server-side assistant/thread/memory capabilities and calls hosted thread-message and tool-output endpoints. `ByokClient` advertises `assistants: false`, `threads: true`, and `memory: false`. The CLI includes local BYOK conversation storage, but its Backboard cloud-memory implementation is a client capability, not the cloud service's implementation. [Backboard client](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/backboard/BackboardClient.ts#L60), [BYOK capabilities](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/byok/ByokClient.ts#L93), [local store](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/byok/ByokConversationStore.ts)
- `ClientRouter` chooses between BYOK and Backboard clients according to configured provider availability and thread source. This establishes provider-client selection. It does not establish task classification, Claude/Codex account quota scheduling, project work allocation, or the approved CrazyAgent fallback policy. [Client router](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/ClientRouter.ts)
- The permission engine evaluates deny/ask rules, tool permissions, read-only behavior, bypass mode, and allow rules. These are process-level tool decisions. The README also warns project MCP and hook configuration can execute local commands. Checkpoint features restore selected changes and have limits, including background-agent edits outside the foreground turn's checkpoint. [Permission engine](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/core/permissions/PermissionEngine.ts), [local configuration](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#local-files-and-configuration), [background agents](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#background-agents)

### Inferences

- Reusing RCLI does not remove the need for Rust-owned canonical project memory, native worker adapters, durable messaging, task/resource routing, mechanical limits, and trusted verification policy. Hosted memory can be optional functionality later, with an explicit account/service dependency. [BYOK capabilities](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/byok/ByokClient.ts#L93), [client router](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/ClientRouter.ts)
- Keep the leader's allowed tool surface small and have Rust validate every dispatch request. A harness permission engine is useful defense in depth; a checkpoint is useful recovery. Neither demonstrates OS confinement of arbitrary shell/MCP descendants or prevents the same coding authority from changing verifier rules. Those boundaries remain CrazyAgent qualification work. [Permission engine](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/core/permissions/PermissionEngine.ts), [MCP warning](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#local-files-and-configuration)
- Recommended next grilling question: Should the first leader use the user's explicit provider key or local compatible endpoint by default, or require a Backboard account/backend? Explain that neither choice is an established way to reuse Claude/Codex subscription credentials, and do not silently enable paid API fallback. [Direct/custom provider documentation](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#use-your-own-model-providers)

### Gaps

- No live authentication, model request, billing behavior, offline turn, encryption review, service-availability measurement, sandbox enforcement, or verifier-integrity test was performed.
- Exact cloud service pricing, retention terms, credential reuse permissions, and dependency licensing beyond the repository's top-level MIT file were not evaluated. Do not infer these from the CLI being open source.
