# Vercel Labs fx for CrazyAgent

## 1. What is current fx, and how mature and reusable is its implementation?

### Takeaway

fx is a native Zig coding agent with reusable agent-loop, protocol and JavaScript library surfaces. It is a credible candidate for replacing or complementing a leader harness, but its experimental status and the distinction between current main and the latest release require qualification before changing CrazyAgent's accepted RCLI direction. This is research and a recommendation, not a runtime selection. [Pinned README](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md)

### Cited Findings

1. Research snapshot: GitHub main was `c7f5a38af216f4bfd5a010ad3ab77059d095829e`, committed 2026-10-17 at 21:27:11 UTC. The latest published CLI release was `v0.0.14`, published 2026-10-16 at 08:27:02 UTC; its tag points to `1a070af32cdfaf8cd0da6de3dc7f053302828b17`. npm also reported libfx `0.0.14`. All implementation links below pin the main revision, not the older release. [Main commit](https://github.com/vercel-labs/fx/commit/c7f5a38af216f4bfd5a010ad3ab77059d095829e), [release](https://github.com/vercel-labs/fx/releases/tag/v0.0.14), [tag reference](https://api.github.com/repos/vercel-labs/fx/git/ref/tags/v0.0.14), [npm package metadata](https://registry.npmjs.org/libfx/latest).

2. The repository declares Apache-2.0, including the SDK package. The Zig package manifest declares an empty package dependency table, and the SDK package has no declared npm dependencies or optional dependencies. This does not mean zero platform or service prerequisites: the native build links libc, the README requires Zig 0.17.0 for source builds, and the SDK supports native Node addons plus WebAssembly. Third-party notices include MIT-licensed cuelume sound material. [License](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/LICENSE), [Zig manifest](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/build.zig.zon), [build](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/build.zig#L43-L70), [SDK package](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/package.json), [notices](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/THIRD_PARTY_NOTICES.md).

3. Role and architecture: the CLI combines the model loop, sessions, permissions, shell/files/web tools, MCP, skills, subagents and inline terminal presentation. It is not simply a command shell and not a Bash interpreter. The user shell is a tool execution backend. The README describes one native binary, with `src/core`, `src/tools`, `src/ui`, model transport and ACP components. [README architecture and features](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md), [shell executor dispatch](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/execution/local_executor.zig#L58-L79).

4. Provider options documented today are Vercel AI Gateway sign-in or API key, ChatGPT subscription sign-in, Grok subscription sign-in and OpenAI-compatible Chat Completions connections, including examples such as Ollama and OpenRouter. The SDK accepts its provider/model configuration per agent; its documentation states credentials and tools come from each host process rather than being restored from a saved conversation. This is useful provider flexibility, not proof of CrazyAgent's multiple-account scheduler. [README authentication](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md), [SDK providers and lifecycle](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#providers), [SDK saved-context boundary](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#durability).

5. Maturity evidence is substantial source infrastructure, not qualification evidence: the README explicitly calls fx experimental. Configured CI builds and tests Zig, checks format and architectural boundaries, smoke-tests a fresh binary, and requires several SDK runtimes. Source inspection counted 92 TypeScript files under `tests/e2e`, 110 TLA files under `tests/tla`, and 10,315 textual Zig `test "` declarations under `src`. These counts include test/support material and do not mean all tests execute or pass in one configuration. The README says E2E uses tmux and Bun. No build, test, binary, model or authentication flow was executed in this research. [Experimental label and contribution instructions](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md), [CI definition](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/.github/workflows/ci.yml), [E2E sources](https://github.com/vercel-labs/fx/tree/c7f5a38af216f4bfd5a010ad3ab77059d095829e/tests/e2e), [TLA sources](https://github.com/vercel-labs/fx/tree/c7f5a38af216f4bfd5a010ad3ab77059d095829e/tests/tla).

### Inferences

The native single-binary CLI may reduce leader-host deployment complexity compared with a JS/Bun application. The library and ACP surfaces are stronger starting points for a controlled integration than screen-scraping a terminal conversation. These are engineering inferences from the published interfaces, not measured speed or reliability comparisons. [CLI and SDK surfaces](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md#embed-and-extend)

### Gaps

No release binary was run, no current CI results were independently verified, and no audit established completeness of its security model. Main has changes after the published release, and source package versions use `0.0.0` placeholders. The SDK README contains a migration notice explaining that `createFxAgent` changed meaning after 0.0.13; exact release API behavior therefore needs a pinned-version acceptance run rather than assuming every main-branch capability ships in v0.0.14. [SDK compatibility notice](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#upgrading), [main revision](https://github.com/vercel-labs/fx/commit/c7f5a38af216f4bfd5a010ad3ab77059d095829e).

## 2. What actually executes commands, and where are the sandbox and secret boundaries?

### Takeaway

The inspected CLI executes real native filesystem and shell operations under its process's OS authority. Its permission engine is an action admission mechanism, not an OS isolation implementation. The README's statement that fx can run inside an agent sandbox is a deployment claim, not evidence that fx creates Vercel Sandbox instances or supplies a bounded local sandbox itself. [README](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md), [native execution](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/execution/command_runner.zig#L1277-L1294)

### Cited Findings

1. Source proof: `executePreparedCommand` chooses direct read-only execution or `command_runner.executeCommandInEnvironment`. The native collector clones the process environment, sets `AI_AGENT=fx`, and uses `std.process.spawn` with real argv, cwd and pipes. Process groups appear in this lifecycle implementation; a process group is not filesystem/network isolation. `read_file` opens a real regular file using a no-follow operation. [Local executor](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/execution/local_executor.zig#L58-L79), [native spawn and environment](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/execution/command_runner.zig#L1277-L1294), [file read](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/tools/filesystem/read_file.zig#L123-L151).

2. Shell state is intentionally user-like: the shell snapshot module captures exported environment and shell functions from login startup and replays that state for later commands. Startup-file changes invalidate it. The snapshot is described as in-memory shell startup state, not an in-memory filesystem or an emulated shell. The macOS spawn helper uses an explicitly supplied environment map or inherited process environment. Consequently, a parent that carries secrets in exported environment must assume child shell commands can receive those exports; no general secret-filtering guarantee was established here. [Shell snapshot implementation](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/terminal/shell_snapshot.zig#L1-L44), [environment construction](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/execution/command_runner.zig#L1282-L1293), [macOS inheritance](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/shared/darwin_process_spawn.zig#L71-L76).

3. Default risk is materially broader than CrazyAgent's admission contract. Current permissions documentation says `auto` directly permits ordinary project edits and recognized commands including dependency installs, tests, builds and development servers; other actions go to a model reviewer, which itself uses tokens. `full-access` disables fx permission checks. `ask` concerns unresolved sensitive calls; the fallback permission gate explicitly allows read-only calls. A user-controlled permission setting is therefore not a substitute for Rust-owned tool admission, immutable verifier policy or OS confinement. [Permissions manual](https://fx.sh/docs/configure-fx/permissions), [permission fallback](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/permissions/permission_gate.zig#L77-L120), [auto classifier source](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/permissions/auto_classifier.zig).

4. Sandbox integration evidence: the pinned README says the binary runs on a laptop, CI or inside an agent sandbox, but the inspected README, SDK README and `src` contain no `@vercel/sandbox` or `Sandbox.create` integration. A source search found no `sandbox-exec`, Bubblewrap, seccomp, Landlock or SandboxProfile implementation in `src`. This is bounded negative evidence from this revision, not proof that every possible execution path is unconstrained. A browser shell backend has an explicit unavailable result when the host supplies no backend, while the browser terminal documentation says the page can supply a workspace that runs commands. That is host delegation, not native isolation. [Pinned README](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md), [browser shell backend](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/tools/shell/browser_shell.zig), [browser terminal host](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#the-fx-terminal-in-a-browser).

5. Network and subprocess authority need external bounds. The CLI deliberately offers web search/read URL tools, model connections and MCP servers; shell commands can also launch real processes. ACP accepts client MCP servers over stdio, HTTP, SSE or the existing ACP connection. No hard outbound network allowlist or complete descendant resource confinement was qualified by this research. [Built-in tools](https://github.com/vercel-labs/fx/tree/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/tools), [ACP MCP transport rules](https://fx.sh/docs/using-fx/acp#prompt-and-mcp-support), [native command runner](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/execution/command_runner.zig).

### Inferences

For CrazyAgent, the safer reusable unit is an admitted fx harness process behind the engine, or a host-tools-only SDK configuration whose tools route to Rust. A clean environment, explicit account references, confined worktree mounts, network policy and descendant limits still need to come from CrazyAgent's execution boundary. Whether the SDK can guarantee removal of every native fallback requires an acceptance test; a custom-tool API by itself is insufficient evidence. [SDK tool API](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#tools), [native executor](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/execution/local_executor.zig#L58-L79)

### Gaps

No live sandbox escape, network restriction, secret-redaction, symlink-boundary, credential storage or child-survival test was authorized or run. No built-in Vercel Sandbox provisioning integration was identified. The absence of familiar sandbox APIs does not replace an independent security review. Provider secrets were not read or supplied.

## 3. Which interfaces and durable capabilities could CrazyAgent reuse instead of RCLI?

### Takeaway

fx is a credible RCLI replacement candidate for the leader-host role because it already supplies headless execution, saved sessions, streamed protocol messages and reusable model-loop APIs. It remains a candidate after qualification: it does not replace the shared Rust engine, worktree ownership rules, independent verification, memory promotion or surviving native-session runners. [Public interfaces](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md#embed-and-extend), [CrazyAgent adopted authority](../../docs/superpowers/specs/2026-10-17-crazyagent-architecture-design.md)

### Cited Findings

| Reuse surface | Proven published or source behavior | CrazyAgent implication |
|---|---|---|
| `fx ask` | One prompt from argv or stdin; final stdout, progress/diagnostics stderr, nonzero error status; `--json` exposes `final_output`; `--resume` selects saved work. [README](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md#for-coding-agents), [ask parser](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/core/cli/cli_ask.zig#L349-L366) | Suitable batch worker surface. Final JSON alone is not a complete interactive supervision or event protocol. |
| ACP stdio | Newline-delimited JSON-RPC 2.0, protocol version 1, initialize first, one active session and prompt per connection. New/load/resume/list/close, prompt/cancel, provider/model/mode controls. [Manual](https://fx.sh/docs/using-fx/acp), [dispatch registry](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/acp/server.zig#L90-L110) | Rust can own a subprocess and protocol bridge without requiring Node for the CLI. Use separate managed processes/connections where concurrency requires them. |
| ACP observation and admission | Streamed message chunks with stable message IDs, tool pending/completion updates, titles and usage; `session/request_permission` callbacks; cancellation also stops pending permission and MCP input. `code` maps to auto, `ask` to ask. [Manual](https://fx.sh/docs/using-fx/acp#sessions-models-and-permissions), [notifications](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/acp/prompt.zig#L214-L230), [permission request implementation](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/acp/prompt.zig#L2439) | Stronger fit than terminal scraping for either client. Permission callbacks need explicit mapping to engine admissions and cannot be assumed to intercept every read-only action. |
| ACP recovery | `session/load` replays saved history; `session/resume` reconnects without replay. Temporary session grants are not restored; saved model/provider choices can be. At connection-loop shutdown the server calls cancellation, releasing pending approval work. [Manual](https://fx.sh/docs/using-fx/acp#supported-acp-methods), [shutdown cancellation](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/src/acp/server.zig#L979-L991) | Saved conversation recovery is useful. It does not establish that an executing native child survives a crashed engine or that reattachment preserves exactly-once effects. Retain CrazyAgent's separate surviving runner. |
| libfx agent/engine | Same Zig core as CLI exposed to JavaScript. `createFxAgent` offers sessions, event consumption, steering and cancellation; `createFxEngine` is one in-memory conversation without a session store and supports checkpoints. Host supplies tools, model and provider. [SDK overview](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md), [engine API](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#without-sessions) | Most flexible custom leader-loop candidate, at the cost of a JS host or new FFI work. A Rust crate or supported Rust embedding ABI was not identified. |

SDK durability is stronger than an ephemeral chat object but narrower than CrazyAgent's operating contract. `createFxAgent` records a prompt before acceptance and steps while running. Node defaults to file-backed sessions under `FX_SESSIONS_DIR` or a system temporary directory; browsers default to memory; Vercel uses Workflow World, with optional custom World storage. A permanent local directory must be chosen deliberately for local-first durability. Each restarted process must supply credentials and tools again. The tool contract distinguishes idempotent replay, write-before-dispatch, stable execution IDs and non-idempotent interrupted calls that may have partly executed. Those are useful recovery primitives, not a universal exactly-once external-effect guarantee. [Durability and tool replay](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#durability), [tool replay contract](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#L185-L225)

Embedding constraints matter for both clients. Release v0.0.14 publishes macOS and Linux archives for aarch64 and x86_64, plus SHA-256 files; that release has no Windows artifact. The SDK native addon supports Node 20+ on those macOS/Linux architectures, with Linux glibc 2.34+. Other Node platforms and browsers use WebAssembly with JSPI; some Node versions need an experimental flag. The README gives Bun 1.4.2+ for its WASM path. `createFxTerminal` embeds the fx terminal UI into an xterm-style browser terminal, with page-supplied storage/sign-in/workspace capabilities. That can help a web desktop, but it is not a Ratatui component and would not itself provide CrazyAgent's complete desktop/TUI product flows. [Release assets](https://github.com/vercel-labs/fx/releases/tag/v0.0.14), [SDK backend matrix](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#runtimes-and-backends), [browser terminal](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md#the-fx-terminal-in-a-browser)

Project and global instructions are supported through `AGENTS.md`, nested project instructions, personal instructions, skills and MCP. CLI conversations persist under `~/.fx/sessions` with continuation and compaction. These are context and conversation mechanisms; no accepted project/global memory promotion approval workflow or independent immutable verifier gate was identified as a reusable equivalent to CrazyAgent's contract. [CLI sessions and instructions](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md), [SDK session semantics](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md)

### Inferences

Compared with the proposed JS/Bun Backboard RCLI leader, fx's ACP and host-tool SDK reduce the amount of interface plumbing that would need to be invented. This makes fx worth a bounded head-to-head qualification before investing deeply in an RCLI-specific persistent bridge. The comparison is against CrazyAgent's recorded RCLI assessment, not a fresh RCLI source audit in this research. [RCLI assessment](../RCLI%20leader%20reuse%20assessment/qualification.md), [fx ACP](https://fx.sh/docs/using-fx/acp), [SDK](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/sdk/README.md)

The recommended prospective role is optional leader-host or coding-worker harness. Keep Rust authoritative for multi-project routing, account and budget admission, worktree ownership, verification, memory approval and durable operation records. Keep native shells as execution mechanisms inside the approved boundary. Keep Claude Code/Codex where their native account and child workflows are required until fx proves equivalent acceptance behavior. No source evidence justifies replacing the whole orchestration product with fx. [CrazyAgent delivery contract](../../docs/superpowers/specs/2026-10-17-crazyagent-architecture-design.md), [fx host surfaces](https://github.com/vercel-labs/fx/blob/c7f5a38af216f4bfd5a010ad3ab77059d095829e/README.md#embed-and-extend)

### Gaps

The decision-changing checks are a pinned-release ACP round trip with streamed output and cancel, kill/reconnect with interrupted tool effects, concurrent authorized account separation, host-tool-only execution with no native bypass, and bounded filesystem/network/descendant probes. These are proposed checks, not new issues, approved work or observed results. No provider execution, account login, install, build, paid service call, code change or accepted architecture change occurred in this research.
