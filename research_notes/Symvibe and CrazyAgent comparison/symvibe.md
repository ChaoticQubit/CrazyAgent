# Symvibe and CrazyAgent comparison

Research date: October 17, 2026. Research only. No application installation, login, provider request, executable download, accepted architecture change or security review was performed. Symvibe behavior below is publisher-documented, not independently runtime-qualified. Local comparison baseline: CrazyAgent commit `8c6d06f81e0d68b3e3c556f3284a58e5e1ceaac8`, its [adopted architecture](../../docs/superpowers/specs/2026-10-17-crazyagent-architecture-design.md), [implementation plan](../../docs/superpowers/plans/2026-10-17-crazyagent-implementation-plan.md) and [decision register](../../docs/agent-decisions.md). A graph query identified these documents before inspection. The shared graph cache was not changed.

## 1. How much of the product and orchestration overlap is already real?

### Takeaway

The assumption that Symvibe is merely a task board containing terminals is incorrect. Its documented product already combines multiple native coding harnesses with an orchestrator, directed commands, teams, status, handoffs, loops, account profiles, memory and session restoration. However, its public descriptions do not establish engine-enforced management of nested native agents or independent verification authority. [Product overview](https://www.symvibe.com/); [cross-harness guide](https://www.symvibe.com/guides/claude-code-codex-gemini-cli-side-by-side).

### Cited findings

**Product and availability.** The public changelog lists initial Hypervibe 1.0.0, build 12, on October 1, 2026, and current Symvibe 1.0.42, build 20, on October 15. The rename preserves accounts, subscriptions, boards and settings. Intermediate releases include sign-in, orchestrator, GitHub panel, voice and Kanban fixes. This is evidence of a shipped, actively changing young product, not evidence of production maturity or reliability. [Changelog](https://www.symvibe.com/changelog).

The application requires macOS 14+ and Apple Silicon. The download page explicitly says there is no Intel, Windows or Linux build. The installer is obtained through an account dashboard, which provides the version, size and SHA-256; the app checks signed updates. This research did not access that dashboard or independently verify signing/notarization. [Download and setup](https://www.symvibe.com/download).

**Workflow and native harnesses.** The board is a pan-and-zoom workspace with real controlling PTYs, interactive native CLIs, a 34-CLI catalog and custom executables. It includes Kanban, notes, checklists, live localhost previews/Web Inspector, Git/GitHub UI and document/diagram/code/Markdown studios. It runs the binaries and subscriptions the user already has. Per-repo/global memory is stored locally and explicitly pushed into consoles; skills and account profiles also live on disk. State uses versioned JSON. These claims describe local state and user-triggered context delivery, not a verified shared-memory authority protocol. [Product overview](https://www.symvibe.com/).

The official tour describes a 52-second recording of the shipping app and links 17 feature demos; the publisher explicitly identifies them as shipped features rather than mockups. The tour covers terminals, voice, teams/mission map, loops and studios. This research inspected the page and embedded media references, not the video frames or a running application. Reproducible public media includes [overview](https://www.symvibe.com/tour), [memory clip](https://www.symvibe.com/media/node-memory.mp4), [loop clip](https://www.symvibe.com/media/node-loops.mp4) and [composer clip](https://www.symvibe.com/media/node-composer.mp4). [Tour description](https://www.symvibe.com/tour).

**What orchestration means here.** The cross-harness guide documents Claude Code, Codex and Gemini side by side, hook-driven working/resting/needs-you status, targeted @mentions/voice, summarized stateful handoffs and native resume. Each vendor retains separate conversations; files, Git and briefs carry work between them. The guide recommends one worktree per writer and ordinary Git merges; it does not claim the app automatically enforces exclusive worktree ownership. [Cross-harness guide, updated October 12](https://www.symvibe.com/guides/claude-code-codex-gemini-cli-side-by-side).

The terms precisely describe model-written instructions submitted to addressed consoles, user-started handoffs/forwards that can wait four hours, and unattended loops. Native permissions remain unless auto-approval is enabled, off by default. Natural-language checks can be wrong. [Terms, sections 7-8, version 2026-10-15.2](https://www.symvibe.com/terms).

The comparison page documents teams with roles, team reports, a composer launching up to 12 consoles, and loops triggered by time, idle or output with a stopping goal. It explicitly says Symvibe runs agents on the Mac, does not offer native remote-machine operation, and is not shell-scriptable like tmux. Running tmux/SSH inside a PTY remains possible. [Official tmux comparison, updated October 13](https://www.symvibe.com/compare/tmux).

**Nested agents: the careful distinction.** The parallel-session guide explicitly distinguishes its independent-session workflow from Claude Code's internal subagents and agent teams; it also recommends using native subagents within a session when appropriate. Therefore, neither “Symvibe has no nested agents” nor “Symvibe manages nested agents across harnesses” is supported. Native CLIs can expose their own features inside the terminals, but cross-harness child identity, per-child stop/pause, ownership, budget accounting and recovery control are not established by the inspected evidence. [Parallel-session guide, especially Patterns and FAQ, updated October 12](https://www.symvibe.com/guides/run-multiple-claude-code-sessions-mac).

**Recovery and credentials.** The documented restoration model is consoles relaunching and offering native CLI resume, with user confirmation. That is distinct from proving uninterrupted live workers survive an engine-only crash. [Official tmux comparison](https://www.symvibe.com/compare/tmux).

Multiple profiles exist specifically for Claude Code and Codex, using `CLAUDE_CONFIG_DIR` and `CODEX_HOME`. A profile can start empty or copy existing sign-in files. The vendor warns that macOS Keychain can prevent full Claude account separation and recommends checking `/status`. It explicitly disclaims account pooling, automatic account rotation and merged limits. Profile separation is not proof of an operating-system security boundary. [Multiple accounts](https://www.symvibe.com/features/multiple-accounts).

**Usage and hosted dependencies.** Usage pills come from short-lived CLI probes; token analytics derive from local session logs. Coverage depends on the data each tool exposes. Provider dashboards remain billing authority. Studios, memory scans and loop goal checks use the user's CLI subscription; reading a usage pill does not call a model. This is useful telemetry but does not establish resource admission or hard spending enforcement. [Usage and tokens](https://www.symvibe.com/features/usage).

The privacy policy says optional live status writes a script under `~/.hypervibe` and adds backed-up hooks to Claude/Codex settings; disabling removes them. Planner command text plus board context goes through Symvibe's gateway to Groq; spoken-reply text goes to Inworld. The snapshot may contain recent orchestrator messages, Markdown paths and snippets. Microphone transcription is local Parakeet, downloaded from Hugging Face. Agent CLIs retain their own provider traffic. Local-first is therefore compatible with hosted planner processing, not a promise that no project-derived text leaves the machine. [Privacy, effective October 15, version 2026-10-15.2](https://www.symvibe.com/privacy).

### Inferences

These sources establish independent native sessions plus application coordination. They do not establish unified control of all native descendants. Their silence about that property remains an evidence gap. [Parallel-session guide](https://www.symvibe.com/guides/run-multiple-claude-code-sessions-mac).

## 2. Should CrazyAgent reuse it, compete, adjust, or stop?

### Takeaway

Continue only with a sharper scope around engine-enforced execution and trustworthy outcomes. Do not build a generic multi-agent terminal board as the differentiator. The useful comparison is between the documented product overlap above and CrazyAgent's [accepted execution and verification guarantees](../../docs/superpowers/specs/2026-10-17-crazyagent-architecture-design.md).

### Cited findings and comparison

**Reuse status.** The personal, nontransferable subscription license restricts source extraction/reverse engineering subject to law and redistribution without permission. It does not authorize implementation reuse. [Terms, sections 3 and 6](https://www.symvibe.com/terms). No official source repository or OSS license surfaced in navigation, the [sitemap](https://www.symvibe.com/sitemap.xml) or targeted search. Treat it as proprietary unless separately authorized. Unrelated “Hypervibe” repositories are not product evidence.

Price is USD 19/month or 190/year, with 10,000 monthly hosted-feature credits and separate agent subscriptions; no free trial is advertised. [Pricing and FAQ](https://www.symvibe.com/). After 15 minutes without verification, the board and input lock while existing agents continue; an expired subscription prevents opening boards. Local JSON remains readable. [Terms, section 2](https://www.symvibe.com/terms).

| Area | Symvibe's documented position | CrazyAgent's accepted target and implication |
| --- | --- | --- |
| Multi-harness workspace | Native CLI consoles, directed commands, roles, loops, handoffs and local task planning are already documented. | These are overlap and usability requirements. More harnesses or more terminal panes is weak differentiation. |
| Policy and coordination | Public descriptions center on user-addressed commands and CLI permissions; resource/task rule routing and engine-mediated peer authorization are unverified. | Rust authority validates scope, destinations, accounts, quotas, dependencies, approved fallback and task mailboxes. Native descendants cannot bypass ownership or budgets. This needs real enforcement proof. |
| Trustworthy completion | No inspected source establishes an immutable independent verifier or protection against worker-modified acceptance tests. Git UI and a role named reviewer do not prove this property. | Human-approved baseline, source-bound verification receipts, protected checks, test-integrity checks and deterministic mandatory/risk-selected gates are substantive candidate differences. |
| Continuity and knowledge | Native resume, local memory push, account profiles and usage telemetry overlap substantially. | Live-worker engine-crash survival, individual native child control, pinned policy, knowledge provenance and human-approved global promotion are narrower target guarantees that must be qualified. |
| Ownership and access | Confirmed paid Mac/Apple Silicon application, no Windows/Linux/Intel build, local execution with hosted planner and subscription checks. | Apache-2.0 original-code intent, independently complete TUI plus Tauri desktop, and eventual additional operating systems are positioning differences, not current feature parity or shipped guarantees. |

CrazyAgent entries describe accepted design, not completed runtime qualification.

### Strategic inferences and useful patterns

1. **Adjust the product claim.** “Several coding agents in one board” is already directly served. Make the value proposition bounded delegated work with inspectable authority, recovery and trustworthy completion. This recommendation follows from the overlap above, not from evidence that Symvibe cannot evolve.
2. **Borrow interaction patterns, not implementation.** Hook-derived needs-you state, an overview beside fully interactive terminals, explicit profile selection, visible native resume and deliberate memory push are useful reference patterns. They reduce attention cost without pretending every harness has identical semantics. [Workflow comparison](https://www.symvibe.com/compare/tmux); [profiles](https://www.symvibe.com/features/multiple-accounts); [product memory description](https://www.symvibe.com/).
3. **Prioritize proof over breadth.** First prove one real Claude/Codex task with isolated writers, nested-child cancellation, engine restart, bounded admission and independent test-integrity verification. Avoid matching studios, drawing, voice or a 34-CLI catalog before the accepted core guarantees work. This is a proposed prioritization, not an accepted architecture change. [CrazyAgent plan](../../docs/superpowers/plans/2026-10-17-crazyagent-implementation-plan.md).
4. **Choose build versus buy by the actual need.** If the need is only visual native CLI supervision, Symvibe merits hands-on evaluation instead of duplicating it. If the need includes enforceable multi-account routing, protected verification and child-level recovery, public evidence is insufficient to conclude it replaces CrazyAgent. No purchase or runtime trial was authorized or performed.
5. **Keep the security claim exact.** Local execution, Git worktrees, native CLI permission prompts and profile folders are not proof of whole-process sandboxing, protected control sockets or CPU/memory/process limits. CrazyAgent's own design explicitly recognizes that same-user unsandboxed processes can defeat file-permission-only verifier separation. Neither product earns a sandbox guarantee from its visual architecture. [CrazyAgent isolation design](../../docs/superpowers/specs/2026-10-17-crazyagent-architecture-design.md).

## 3. Gaps, limits and next evidence

1. **Architecture and reuse:** No public Symvibe source code, component license, SDK or stable automation API was identified. Language/framework, dependency composition, event durability and internal authorization implementation are unknown. The paid license is confirmed; lack of a search result does not prove a separately licensable integration cannot exist.
2. **Nested orchestration and recovery:** No evidence establishes discoverable per-child identity, independent pause/stop/resume, child budget enforcement, cross-harness nested-agent supervision or live-process continuity across an app/engine crash. A real native CLI running in a PTY may support its own delegation; that does not establish unified application control.
3. **Verification and risk gates:** No independent immutable acceptance baseline, protected verifier, test-integrity enforcement, mandatory pre-merge checks, security gate or deterministic risk policy was found. This is undocumented in the inspected public pages, not a tested absence.
4. **Knowledge, accounts and isolation:** Provenance, human approval of global promotion, scope-restricted peer communication, pinned asset versions, plugin compatibility, hard per-account budgets, resource reservation, filesystem/network confinement and protected Git metadata remain unverified. The documented Keychain caveat is a concrete account-separation limitation, not proof of a vulnerability.
5. **Evidence quality:** The source set is the official homepage, sitemap, tour, two workflow guides, accounts/usage features, comparison, download page, changelog and October 15 terms/privacy revisions. Searches included Symvibe/Hypervibe source/license and site-scoped sandbox/subagents/memory/skills/router/verification/plugins. Marketing breadth and a publisher-labelled shipping demo do not independently verify every adapter. No installation, billable request, hosted account, runtime fault test or repository audit was performed. The next bounded research action is a feature-by-feature evaluation brief for an owner-approved trial, with the unknown guarantees above treated as explicit questions.
