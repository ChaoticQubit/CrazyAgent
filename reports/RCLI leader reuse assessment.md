# Reuse RCLI Without Surrendering Engine Authority

**Yes: reuse RCLI as CrazyAgent's editable leader harness, with the Rust engine retaining execution, routing and policy authority.** This implements the owner's DEC-010 selection rather than reopening it. MIT licensing permits source modification and redistribution with the required notices. RCLI supplies a credible reasoning-process foundation, headless execution and extension points for orchestration tools. It does not already supply CrazyAgent's custom two-client experience, native worker adapters or trusted verification boundary. The smallest integration starts with a pinned sidecar and introduces a thin fork only where host control requires changes. This is static source qualification, not an executed integration or security audit. ## An editable sidecar preserves the Rust engine

Assessment targets commit `51bee17e02344de5fffd89523ce2b73d5042f216`, observed October 16, 2026, whose manifest identifies version 3.0.4. **RCLI is TypeScript/Bun, not a Rust library.** Its private package exposes a CLI, without an established stable embedding SDK. A separately managed process therefore fits the existing implementation better than importing internals or porting its reasoning loop. Its release builder declares macOS, Linux and Windows targets; distributed compiled binaries are documented as requiring neither Bun nor Node installation. These establish packaging intent, not CrazyAgent platform qualification. Bundled dependency notices, signing and reproducibility remain unexamined. ([Manifest](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/package.json), [build targets](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/scripts/build-release.ts), [installation](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#install))

Recommended ownership is explicit: both custom interfaces connect to Rust; Rust manages the RCLI leader and separately adapted Claude/Codex workers. RCLI proposes plans and requests operations through narrow engine-owned tools. Rust checks approved limits before dispatch. RCLI's native subagents remain distinct from those worker harnesses: documented nesting stops at two levels, background concurrency at four, and headless background execution runs inline. Those limits neither establish nor preclude engine-managed worker scale. ([Subagents](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#custom-sub-agents))

## Structured output helps, but interactive control needs qualification

RCLI supports `--print`, piped prompts, JSON event output and resumable sessions. Events contain session IDs, sequence numbers, timestamps, sources and typed payloads. Configured MCP servers initialize before the controller, and the tool registry supports registration and filtering. These provide a plausible adapter surface for CrazyAgent's primary conversation without scraping RCLI's TUI. However, stdin is read to completion: **NDJSON output is not evidence of a persistent bidirectional host protocol.** ([Headless modes](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#one-shot-and-json-modes), [event stream](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/core/session/JsonEventStream.ts), [tool registry](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/core/tools/ToolRegistry.ts))

First qualify one leader turn proposing a plan, approval in CrazyAgent, and resumed execution through Rust MCP operations. If restart/resume cannot support the required interaction, add a small host protocol for messages, approval responses, cancellation and events, separate from rendering. Headless permission requests otherwise requiring a prompt are denied unless explicitly allowed; silently enabling bypass would defeat the approval design. Safe reconnect, replay, descendant cancellation, idempotent dispatch and leader-only tool restriction remain untested. ([Entrypoint and permission context](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/entrypoints/cli.tsx#L278))

## Open CLI source does not include every backend capability

**A Backboard account is optional:** direct Anthropic, OpenAI, Google and OpenRouter credentials and compatible custom endpoints are documented. No inspected evidence establishes reuse of Claude Code or Codex subscription credentials. Existing worker authentication therefore must not be treated as leader authentication, and paid API fallback requires explicit selection. Exact service pricing and terms were not assessed. ([Direct providers](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#use-your-own-model-providers), [custom endpoints](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/README.md#custom-model-providers))

The Backboard client calls hosted memory services; the direct-provider client explicitly reports `memory: false`, alongside local conversation storage. Source availability does not supply the hosted service implementation. Likewise, RCLI's client router selects provider clients, not task-specialized native workers against account limits. Rust still needs canonical project context, durable messages and the approved task/resource router. ([Backboard capabilities](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/backboard/BackboardClient.ts#L60), [direct-provider capabilities](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/byok/ByokClient.ts#L93), [client router](https://github.com/Backboard-io/Backboard-R-CLI/blob/51bee17e02344de5fffd89523ce2b73d5042f216/src/providers/ClientRouter.ts))

## Conclusion

The qualification boundary is whether RCLI can operate with restricted orchestration authority while the engine enforces DEC-009's initial approval and bounded dispatch. Harness permission rules and checkpoints do not establish confinement or protect verifier policy from arbitrary shell/MCP descendants. Keep trusted rules and accepted verification receipts outside coding authority, and test that separation independently. No runtime, authentication, concurrency, performance or verifier-integrity test was performed. This choice reduces reasoning-runtime work; it leaves those product obligations intact.
